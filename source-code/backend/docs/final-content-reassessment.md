# Final-content accuracy reassessment

The final accuracy workflow is distinct from exact-source linking. `accuracy_jobs.py` uses the existing durable `EvidenceLinkJob` store with `job_kind=accuracy` (migration 0022). Source-link workers/listings explicitly filter `job_kind=evidence`; the document worker services both types. Existing rows default to evidence. Batch queue creation validates all snapshots and image gates before any writes, serializes against pending paper work and uses request IDs for duplicate-free receipt recovery.

Admin APIs under `/api/v1/admin/official-paper-reviews/{paperId}`:

- `GET /accuracy-readiness`: per-question image blockers, stale-assessment status, current content at 75% or lower and eligibility.
- `GET /accuracy-jobs`: private recent durable job history.
- `POST /accuracy-jobs`: explicit question snapshot batch. Each item supplies requestId, number, expectedRevision, expectedContentHash and expectedAnalysisVersion. Mutations require CSRF; all endpoints require Admin.

The worker checks active Admin permissions, snapshots, original PDF checksums, selected crop bytes and review state. It supplies original paper, scheme and report pages plus reviewed crops to the existing account router, treating all source/content/old notes as untrusted data. Report pages can include the earlier source comparison's verified scope when no per-part report link exists. A report not checked cannot receive a checked score. No source text or image is generated or overwritten.

Model output must assess every actual part once, use only supplied original pages, provide independent wording/marking/visual confidence, reasons and paper/scheme/report checks. Current percentages are constrained by dimensions, weakest source/part and explicit manual-review flags. Earlier checked source findings at or below 75% remain capped for Admin adjudication; the model cannot silently settle a publisher contradiction. These are estimated fidelity judgements, not calibrated correctness probabilities. Human decisions are not overwritten.

One question is the reassessment unit, preserving shared context and avoiding reruns of unaffected current questions. The request is limited to 24 original pages/selected crops and the configured input/image limits; evidence-specific output cap defaults to 8000 tokens. Excess/invalid/missing input fails closed. Source/model failures do not retry automatically. Processing jobs interrupted for 15 minutes fail without dispatching again. A deliberate new job is required for a retry; inspect history first.

No long transaction/question lock spans the paid call. Revision/hash and analysis-history checks run again before saving. Fresh analysis, normal guarded AI status changes and completed job receipt commit atomically. The final-source-accuracy-v2 workflow additionally checks published curriculum evidence, may fill previously undecided supported mappings, and automatically releases eligible Tutor items. Human mapping decisions, withdrawals, frozen attempts, marking rules, image approvals and source associations are preserved. Curriculum and release transitions are audited separately. A nested release savepoint preserves the paid assessment when release writes fail; retrying releases makes no model call. Asset edits invalidate the hash as before.

Frontend `AccuracyReassessment` is available in the accuracy overview and selected-question review, with unsaved-edit protection, explicit paid-call confirmation, resumable progress and distinct image/content queues. A completed final assessment uses the existing strict >75% approval policy, still subject to all evidence/visual/coverage gates; scoring readiness and Student access remain independent gates. Eligible Tutor releases follow automatically; formal-exam publication stays separate.

Tests: `test_accuracy_reassessment_jobs.py`, plus exact evidence, analysis history, official review and auto-approval regressions. Implementation tests use synthetic original PDFs/crops and `FakeAIProvider`; they make no paid model calls.

## Curriculum and workflow integration (v2)

`paper_curriculum.py` selects at most 40 published same-course/subject textbook passages, up to three per topic, bounded to 2,200 characters each. This is a candidate search, not proof that an omitted topic is outside coverage. Model citations must use provided chunk IDs. Existing manual decisions are never replaced; a mismatch is retained as a conflict. Only supported proposals with exact evidence and independent mapping confidence of at least 90% may populate an undecided mapping. Mapping confidence is not extraction accuracy. Saved checks include immutable topic publication, document/chunk IDs/hashes, model provenance through their parent assessment, and a mapping fingerprint. New publication/archival or material evidence/mapping changes invalidate automatic release at access time.

`TutorPaperRelease.snapshot` stores the automated policy and curriculum dependency metadata; existing JSON and analysis stores support this without a new migration. The shared `validate_release` is used for manual release, automatic release and live access. For partial release it validates the actual shared context and selected part using the ordinary approval gates, retains reconciled whole-question marks and requires no unassigned candidate images. Other siblings do not grant eligibility or need to be approved. The final model must explicitly confirm independent answerability for automatic release. Unsupported text marking remains blocked; existing manual drawing is the only supported manual assessment path. Nothing here promotes a prose rubric to executable scoring.

Additional Admin APIs:

- `GET /api/v1/admin/official-paper-reviews/workflow?documentId=UUID` (repeat up to 100 IDs): batched typed source-aware summaries. Four paper milestones, three independent companion milestones, per-paper scope, current counts, exclusions and action links. A bounded set of bulk queries avoids a query per table row/part.
- `GET /{paperId}/chat-release-readiness`: authoritative per-part manual-release eligibility and blockers.
- `POST /{paperId}/auto-tutor-release`: revision-safe recovery over saved assessments, no paid call. Explicit withdrawals remain protected; an explicit manual re-enable can restore eligibility when all gates pass.
- `GET /{paperId}/questions/{number}/accuracy-context`: Admin-only original-page/reviewed-crop and published-passage context for controlled external evaluation. Contains private licensed source material, never Student data or credentials. Do not commit its response.

`AKURU_PAST_PAPER_AUTO_RELEASE_ENABLED=false` pauses new automatic releases and their retry action. It does not withdraw existing items. Use the audited Admin withdrawal to stop existing access. No database downgrade is needed for the additive JSON fields, but older strict analysis readers cannot parse them. Use compatibility commit `73fc05934c16f6caf1e7b408d6b6fdc3def69e3b` as the backend rollback floor, not the unmodified older release. Before rollback set `AKURU_TUTOR_PAST_PAPER_CHAT_ENABLED=false` to close the practice channel because the older access validator lacks new publication dependencies. Keep it disabled until the guarded release is restored. The compatibility schema preserves new assessment history; do not strip fields or delete records to make an older reader work. Old workers must not process new v2 jobs during rollback: stop the document worker, let active work finish or fail safely, inspect job receipts and do not process pending v2 jobs with an older worker. Restart API/web at the compatibility floor; keep v2 job processing paused until a matching worker is restored. Run health and protected-API checks. Prefer disabling automatic release or rolling forward when possible. Retain completed assessments and release history.

Paper step denominators retain all imported parts, including exclusions, and require a nonzero reconciled expected question inventory; exclusions do not silently turn the paper green. No-source/no-comment/unchecked are separate outcomes. Workflow summaries do not rewrite raw extraction-job history. The Admin table keeps extraction percentage and errors visible alongside derived workflow status.

Tests: `test_paper_workflow.py` adds partial release, strict threshold, mapping uncertainty/conflict/unseen references, cross-subject search, publication invalidation, withdrawal/retry, release-failure recovery, scoped companion statuses, role/CSRF controls and bounded aggregation queries. See the workflow TODO for actual production acceptance evidence.

Manual low-confidence adjudication is explicit and bound to the exact assessment ID and content hash, stored as an Admin approval audit event. A human approval from before a newer low-confidence assessment is not silently reused. Saving a newly approved part triggers the same guarded release check without an additional release click. Existing human status is preserved while a genuinely new source concern still appears in the manual queue. Unsupported scoring still blocks release and the Assessed milestone, regardless of content approval.

The Assessed badge exposes both `checked` (current v2 comparisons performed) and `completed` (all assessment, mapping, visual and supported scoring gates resolved). A finished comparison with remaining blockers is amber even when zero subparts are ready; it is not reported as not started. Referenced missing diagrams/tables use the same visual-requirement check in approval, image queues and workflow summaries.

The opt-in `scripts/evaluate_paper_workflow.py` captures original/crop context through authenticated Admin APIs and uses a separate evaluation key. It defaults to read-only dry run, requires ignored output and explicit live/apply/rate confirmation, reserves a conservative multimodal spend bound before dispatch, prohibits long-context pricing, preserves unknown usage reservations and never retries paid calls automatically. Existing saved assessments prevent accidental repeat generation. The GPT-6.1 Sol price bound was checked against https://developers.openai.com/api/docs/models/gpt-6.1-sol on 2026-11-11; other models are rejected by this runner until their rates are reviewed. No evaluation key is copied to production.

Queued requests explicitly bind `workflowPolicy=final-source-accuracy-v2` when the Admin confirms the new workflow. Legacy/pending requests without this marker remain assessment-only: they do not fill mappings or automatically release Student content. Idempotency compares normalized versioned requests and never upgrades an old receipt to new release consent. The new UI sends the policy marker; old clients remain safe while operators refresh them.

All newly released snapshots, including explicit manual releases, bind the exact current topic-publication IDs and source/visual/block content hash in a composite release fingerprint. New publication versions create a new immutable release row after revalidation rather than rewriting the old snapshot. Book archival, missing publication or material source/visual edits fail closed at access time. Legacy releases without these dependencies require explicit revalidation; their rows and frozen attempts are retained. Live Student selection is restricted to the requested subject and current question revision before deeper checks.

Partial Tutor practice never grants a full marking-scheme or examiner-report page URL, even after answer reveal: such pages can contain unreleased sibling answers. It reveals only the selected part's approved marking/guidance and approved private answer visuals. Question-paper context pages remain available. Full official-source access stays in its separate authorised workflow.
