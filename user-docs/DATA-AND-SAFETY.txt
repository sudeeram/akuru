AKURU: DATA AND CURRENT LIMITS
==================================

Admin manages accounts, curriculum and learning documents. Each parent sees
only linked children; students see their own work. Learning resources are
shared by subject after Admin approval. Student answer attachments remain private
to the child, their linked parent and Admin.

The backend stores accounts and enrolments in PostgreSQL. Protect database
backups because they contain family and student records. Uploaded learning and
answer files will use private object storage when that service is implemented.

Passwords are stored only as Argon2 hashes. Newly created Parent and Student
accounts must replace their temporary password on first sign-in. AKURU contains
no demo credentials. Sign out on shared devices.

No uploaded file goes to an external AI service. Automatic PDF extraction,
equation/diagram ingestion, AI tutoring and generated images/videos are not
connected. Admin enters and checks questions and unit mappings manually.

Numeric final-answer checking does not assess every method step. Written work
needs parent review. Study suggestions are rule-based; scores are not predicted
grades. Course names and subject settings do not certify content as official
Edexcel material. Use only resources the family is entitled to store and study.

Before public hosting, implement the production backend, private credentials,
account lifecycle, HTTPS, database/object storage and backups described in the
architecture documentation. The backend folder currently contains design only.
