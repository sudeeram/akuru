AKURU ADMIN GUIDE
======================

Sign in with the Admin account created through the secure backend bootstrap
command. AKURU contains no default Admin password.

1. ACCOUNTS AND ENROLMENTS

Open Accounts & enrolments. Select the parent role, enter a unique username,
name and initial password of at least 8 characters, then Create account.

To add a child, choose student, enter their own username/name/password and
select the existing parent account. Choose iGCSE, Grade 10 or Grade 11,
then select every completed/current Grade + Term combination. For Grade 10
Term2, select Grade 10 Term1 and Grade 10 Term2. Also select the subjects.
Create account.

Use Edit beside an existing child to change their parent, current grade/term,
progression combinations or subjects.
Submit an active mock before changing the child's enrolment. Legacy learners
need confirmation; do not infer an iGCSE grade from an old school-year label.

2. TEXTBOOK STRUCTURE AND TOPIC SOURCES

Open Textbook structure. Create or select the Edexcel iGCSE textbook for the
correct subject. Create each Unit or Module as a group, then create its child
topics. For Chemistry, Unit 1 is the group and States of Matter is Topic 1.
Codes must be unique within their textbook. Later topics can be added and
published independently without changing an already released Topic 1.

Upload each PDF or image to the child topic it describes. The subject is taken
from the textbook and cannot be changed to another subject during upload. Open
Documents & textbooks to monitor processing and complete every required page
or extracted-content review. Finishing extraction review makes the source ready;
it does not publish the topic.

Open Manage topic sources for the topic. Every source has a role:

- Primary text is the canonical reviewed source used for retrieval.
- Supporting or reference text is included only when explicitly selected and
  fully reviewed.
- Visual reference retains a scan for provenance and selected illustrations,
  while excluding its duplicate OCR text from normal retrieval.

For the Chemistry States of Matter comparison, attach exactly the clean v2.1
PDF and the original scan, then use Apply recommended v2.1 source roles. Confirm
that v2.1 becomes Primary text and the original scan becomes Visual reference.
The action changes no published content and is recorded in the Admin audit.

Use the Topic review checklist to see unresolved pages, blocks, Chemistry
notation, tables and selected visuals. Its Review links open the corresponding
document work directly.

For a Visual reference, open Select and review visual assets. For each diagram,
image or table that should support learning, check the exact source page, correct
its caption and write a useful accessible description. Save for review while it
is unfinished, Approve when it is accurate, or Exclude it. A selected but
unapproved visual blocks topic publication. Unselected OCR from the visual
reference does not block an otherwise reviewed primary source.

Before publishing, confirm the source preview contains only the intended text
and approved visuals. Publication creates an immutable topic-content version.
Visuals retain their source document, version, checksum, page and crop location.

3. DEFINE TERM COVERAGE

Open Grade & term coverage. Choose the subject, grade and term. Use Load saved
coverage to see the existing selection. Select the complete set of published
topics that the term exam covers and Save term coverage. Repeat for other
grade/term pairs.

Student coverage is cumulative across saved progression combinations. A Grade 10
Term2 student receives the union of Grade 10 Term1 and Grade 10 Term2 coverage.
Grade 11 does not inherit Grade 10 automatically. An empty union makes no
questions, Tutor sources or flashcard decks eligible.

4. PAST PAPERS AND SUPPORTING DOCUMENTS

Return to Documents & textbooks. Select Past paper and choose a published
textbook in the same subject. The textbook must already have published topics.
Upload the paper. Then upload its Marking scheme and Examiner report, selecting
the related same-subject past paper. Upload Reference material separately.

5. MAP EVERY QUESTION

Open Question mapping. Select the subject and paper. Read the original document
in Documents & textbooks and manually enter each question/subpart, title, text,
marks, answer type, worked explanation and marking points. Add optional hints.
Select every textbook topic required to answer it, then Save reviewed question.

Every question needs at least one topic. A multi-topic question is allowed only
when all its topics belong to the selected textbook and subject. Mathematics
questions cannot use Chemistry topics. Biology, Chemistry, Physics and Human
Biology are separate subjects.

The document worker extracts page text, equations and diagram evidence for Admin
review. Do not publish a question whose essential diagram or context is missing.

6. APPROVE THE COMPLETE PAPER

After every question is entered and reviewed, return to the paper in Documents
& textbooks. Check the confirmation that the entire paper has been entered,
mapped and approved, then Approve document. Question edits require this sign-off
again. Confirm completeness against the original PDF; the local portal cannot
automatically count its questions.

A term mock includes a question only if EVERY required topic is covered for the
student's current grade and term. With covered Topics 1 and 2, a question requiring
Topics 2 and 3 is excluded. Missing material never triggers a full-syllabus fallback.

Full papers, marking schemes and examiner reports stay in the Admin library.
Students practise eligible questions. Approved textbooks and reference resources
are visible to families enrolled in that subject.

7. CONFIGURE OPENAI ACCOUNTS

Ask the server administrator to add each OpenAI key to the backend-only
AKURU_OPENAI_ACCOUNT_KEYS JSON map. Do not paste API keys into the portal.

Open OpenAI accounts in the Admin navigation. Add a friendly name, the exact
credential alias from the dotenv map, a model and a unique priority from 0 to
100. The lowest number is tried first. Accounts intended to back up one another
must use the same model. The portal shows whether a credential alias is
configured, but it never displays its key.

Disable an account to stop new work from using it. Editing and saving an account
resets its recorded health so AKURU can try it again after credit is added or a
configuration problem is corrected. A failover restarts one complete AI request
and can take longer, but it uses the same prompt, schema and curriculum context.

STEP 17: ASSESSMENT AUDIT
Open Assessment audit in the top navigation. Select a result to inspect its
marks, confidence, model, prompt/engine versions, sources and marking evidence.
Inspect the original submitted working where available. You can correct each
marking decision and teaching feedback, give a reason, and publish a reviewed
result. Earlier versions and the reviewer provenance are retained.

Reassess and create new version sends the entire assessment through AKURU's
OpenAI marking workflow. It can still produce a result needing human review.
After a failure, retry the same operation. If you left the page during an
uncertain request, refresh the audit to check whether a new version was saved.
The document review screen shows the original page beside extracted content.

STEP 18: VISUAL MEDIA
Open Visual media in the top navigation. Choose a subject and an approved
textbook source. Geometry, forces, circuit and graph visuals are generated by
validated code and publish immediately. Use the documented JSON fields shown
on screen; AKURU rejects unsafe ranges and invalid triangle/plot data.

Conceptual illustrations use OpenAI and consume account credit. They remain
private after generation. Compare the image and description with the linked
official source, add review notes, then Publish illustration or Reject. A
published illustration supports the explanation; it never replaces the
official textbook, question or marking scheme. Video generation remains a
future optional feature and is not enabled in Phase 1.
EVALUATION AND RELEASE GATES

Use Evaluation gates before enabling automatic assessment feedback for any subject. Create a corpus from licensed source material and independently reviewed expected results. Include cases for inventory, OCR, equations, diagrams, unit mapping, marking and method marks, feedback/grounding, and repeatability. Review every expected value before approving the corpus.

Run each candidate model and prompt version against the approved corpus. AKURU displays every metric and blocks a release if one is below its threshold. Activate automatic feedback only for a passing run. A later model or prompt change will automatically return that subject to review-required behavior until its matching regression passes.
SECURITY AND OPERATIONS

Use the Operations page to review failed document jobs, provider failures, AI token usage, latency alerts and recent administrative audit events. Investigate alerts before publishing content or enabling automatic feedback. Never paste OpenAI keys, database passwords, student answers or private files into support messages.

Authorized deletion requests are performed by an operator with the backend retention command. Preview first with `python -m app.retention --student-id CHILD_UUID`; apply only after verifying the requesting guardian and recording the request, using `--apply`.
TUTOR PRESETS

Open Tutor presets to manage the child-safe AKURU hero avatars and voice styles offered to Students. You can enable, disable and reorder a preset. Disabling it prevents new selections but preserves existing profile history. Admins can view a Student's tutor profiles for support but cannot create or edit a profile as that Student.
