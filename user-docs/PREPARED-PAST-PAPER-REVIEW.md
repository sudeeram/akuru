# Reviewing prepared past-paper corrections

An Admin can review a correction prepared by a developer without repeating unchanged question reviews.

Open the paper's review page and select the question. Save or discard any current edits. Expand **Prepared developer review**, load readiness, and paste the prepared JSON supplied by the developer. Stage it and inspect the preview: check the changed text, source references and affected subparts. Confirm and apply only when the preview is correct.

Applying a correction does not publish a complete exam. The result records newly checked evidence separately from unchanged findings carried forward from an earlier review. A high source-confidence percentage does not prove automatic marking is supported. Read the remaining scoring, curriculum and Tutor-release blockers before releasing content.

If the preview reports a conflict, ask for a fresh package based on the current question. Do not change revision/hash values yourself. Existing approved siblings should not need another manual review unless their shared sources or context changed.

Prepared packages and source exports are private. Do not put credentials, licensed documents or exports in GitHub.
